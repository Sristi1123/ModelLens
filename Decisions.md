# ModelLens — Design & Implementation Decisions

## 1. Why this approach?

I chose to build ModelLens as a frontend-first product rather than turning the challenge into a full ML application.

The main goal of this submission was to show how a user could interact with a machine learning product and understand a prediction without needing to know how the model works internally. Keeping the demo in the browser made it possible to focus on that experience instead of spending most of the available time setting up a backend, API routes, CORS, and deployment infrastructure.

I also wanted the demo to be easy to run and explore. A reviewer can open the page and immediately interact with the datasets and predictions without waiting for a server or configuring anything locally.

The limitation is that the predictions in the current demo are not being generated by the trained `.pkl` models. They are simplified demo logic intended to represent the product experience rather than make production-level predictions.

## 2. One trade-off I made

The biggest trade-off was choosing a working interactive demo over implementing the complete ML pipeline.

I kept the datasets and interactions small enough that the main experience could be completed and polished within the challenge time. Instead of connecting every dataset to a real model and building an API around it, I focused on making the prediction flow understandable and responsive.

With another week, I would connect the frontend to the actual scikit-learn models, expose predictions through a small Flask or FastAPI service, and generate real feature-importance explanations using SHAP or a similar approach. I would also add proper validation, loading/error states, and tests for the prediction endpoints.

## 3. Where I used AI tools

I used ChatGPT as a development assistant during the project. It helped me explore implementation approaches, troubleshoot code, and work through parts of the CSS and JavaScript structure.

I did not treat the generated code as the final implementation. I tested the interactions myself, changed the layout and styling, checked the responsive behavior, and removed or changed anything that did not fit the direction of the page.

I also reviewed the prediction logic and made sure the UI behaved as expected when the input values changed. For the final page, I intentionally avoided fake testimonials, fake user numbers, and invented company logos because they would make the product look more polished at the cost of being misleading.

The final implementation is therefore a combination of AI-assisted development and my own decisions about the product structure, visual design, interactions, and what was worth keeping.
